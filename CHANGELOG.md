# Изменения

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Не выпущено]

### Добавлено
- `bin/zapret-manager doctor` — диагностический отчёт: модули ядра, счётчики
  nfqueue, давность списков, проверка файлов, на которые ссылается стратегия.
- Снимки состояния перед перезапуском службы
  (`~/.local/state/zapret-discord-youtube/incidents/`).
- Плановый перезапуск службы как обходная мера: `zapret-manager autorestart on 12`.
  Только systemd, по умолчанию выключен.
- `zapret.lock` с пинами версий и контрольными суммами; `tools/update-lock.sh`
  для их пересчёта. Без заполненных сумм — предупреждение,
  с `--strict` — отказ.
- Тесты (`tests/run.sh`) и линтер переносимости (`tools/lint-portability.sh`).
- CI: shellcheck, переносимость, синтаксис конфигов, тесты на GNU и на busybox,
  `nix flake check`.

### Изменено
- Загрузчик стратегий вместо 21 самостоятельного конфига: общий `config`
  собирает `NFQWS_OPT` из фрагмента `strategies/<имя>` и включённых
  `fixes/<имя>`. Было ~3500 строк с дублированием, стало ~230. Основа взята
  из экспериментальной ветки strategy-loader.
- Каталог `configs/` заменён на `strategies/`; добавлен `fixes/`.
- Выбор стратегии — запись имени в `/opt/zapret/zapret.strategy`, а не
  подмена файла конфигурации.
- `config` обновляется только если пользователь его не правил; иначе рядом
  появляется `config.new`.
- NixOS: `configName` → `strategyName`, `extraConfigs` → `extraStrategies`,
  `derivedConfigs` → `derivedStrategies`; добавлены `extraFixes` и
  `enabledFixes`. Старые имена опций переименованы через
  `mkRenamedOptionModule`. `nfqwsAppend` теперь создаёт обычный фикс, из-за
  чего удалён awk-скрипт, вживлявший правила в середину `NFQWS_OPT`.
- Скрипты переписаны и разложены: `bin/` для команд, `lib/` для общих модулей.
  `setup.sh` остался точкой входа для `curl | bash`, но стал тонким бутстрапом.
- Файлы проекта переехали из `~/zapret-configs` в каталоги XDG. Перенос
  выполняется автоматически при первом запуске `zapret-setup`.
- Вместо алиасов в конфиге оболочки — команды в `~/.local/bin`.
- Конфиги переименованы к единому виду: `general-alt` вместо `general(ALT)`,
  `general-simple-fake` вместо `general (SIMPLE FAKE)` и так далее.
  Старые имена принимаются с предупреждением.
- `/opt/zapret` остаётся под root. Запись в hostlists идёт с повышением
  привилегий по факту недоступности пути, а не по предположению о владельце.
- Блок в `/etc/hosts` ограничен маркерами: обновляется целиком и удаляется,
  а не накапливается.

### Исправлено
- `exit` внутри подстановки команд не прерывал скрипт: при отсутствии sudo
  `setup.sh` продолжал работу с текстом ошибки в переменной, а `install.sh` —
  с пустой, выполняя команды без повышения прав.
- `update-rd.d` вместо `update-rc.d` — автозапуск на AntiX не настраивался.
- `modrope` вместо `modprobe` — модуль `nfnetlink_queue` не подгружался
  на Secureblue.
- `ps -p 1 -o comm=` не работает с busybox ps: на Alpine система инициализации
  не определялась. Теперь читается `/proc/1/comm`.
- Пустой каталог конфигов давал меню с несуществующим пунктом (нет `nullglob`).
- `rm -rf "$HOME/tmp"/*` удалял пользовательские файлы; используется `mktemp`.
- Коммит проекта всегда сохранялся как `main`: имя каталога в архиве ветки
  не содержит хеша. Теперь берётся из GitHub API.
- Временные каталоги обновления не удалялись из-за `exec` в обход EXIT-trap.
- SELinux-модуль собирался прямо в каталоге репозитория, оставляя `.mod`/`.pp`.

### Удалено
- `configs/old configs/` — стратегии больше не работают.

### Устарело
- `setup.sh` как установщик (стал бутстрапом), `install.sh` и
  `utils-zapret.sh` — оставлены шимами. **Будут удалены через два релиза.**
- Старые имена конфигураций. Таблица синонимов —
  `configs/legacy-names.map` и `legacyConfigNames` в `nixos/package.nix`.
  **Будет удалена через два релиза.**

### Добавлено (продолжение)
- Схема стратегий из экспериментальной ветки: общий загрузчик `config`,
  фрагменты `strategies/`, компонуемые `fixes/`, состояния
  `zapret.strategy` и `zapret.fixes`.
- `zapret-setup --uninstall` и `--purge` — полное удаление с показом плана.
- `zapret-manager report` — отчёт для issue одним файлом (права 600).
- Переопределение внешних адресов через переменные окружения
  (`ZDY_REPO_SLUG`, `ZDY_BRANCH`, `ZDY_FLOWSEAL_SLUG` и другие) для проверки
  на форке.
- Контрольные суммы для файлов службы dinit (`dinit_sha256` в `zapret.lock`).

### Исправлено (продолжение)
- `shopt -p nullglob` возвращает 1, когда опция выключена: под
  `set -euo pipefail` это молча роняло `zapret-config --list`.
- Каталог состояния и снимки инцидентов создавались с правами 755, хотя
  содержат записи conntrack. Теперь 700, отчёт — 600.
- `package.nix` патчил `WS_USER` в несуществующем каталоге `configs`, и патч
  всё равно затирался последующим копированием `config`.
- Проверка ссылок на файлы стратегии была продублирована в трёх местах.

### Исправлено (по результатам тестов на Linux Mint)
- **Команды не запускались вообще.** `~/.local/bin/zapret-*` - это симлинки,
  а `pwd -P` раскрывает только каталог, не сам файл: скрипт искал `lib/`
  рядом с симлинком и падал с "Нет такого файла или каталога". Добавлено
  разрешение симлинков перед подключением библиотек.
- `zapret-restart` был симлинком на `zapret-manager` и открывал меню вместо
  перезапуска. Теперь разбирается имя вызова.
- Опечатка `ACTIVE_DISCORD_UDP.binn` в `strategies/general-alt-8`:
  `install_easy.sh` отказывался стартовать, служба оставалась без обхода.
- `strategies/general-exp` ссылалась на `quic_initial_4pda.to.bin`, которого
  нет ни в поставке zapret, ни среди докачиваемых файлов.
- Меню показывало `general-alt-10` сразу после `general-alt`: сортировка была
  лексикографической. Добавлена естественная сортировка чисел.
- Остатки английского в выводе: приглашения ввода, "Press Enter to continue",
  "TCP and UDP", "updated N day(s) ago". Давность списков теперь склоняется
  по-русски.
- `~/.local/bin` часто не в PATH (каталог создаётся уже после входа в
  систему). Установщик предлагает дописать строку в rc, а не только
  предупреждает.

### Добавлено (по результатам тестов)
- `tests/fake-binaries.txt` - список .bin, доступных во время работы, и тест,
  проверяющий по нему все ссылки во фрагментах. Именно этот класс ошибок
  (опечатка в имени файла) прошёл мимо `bash -n` и разбора фрагментов.

### Исправлено (после сверки с каталогом bin/ у Flowseal)
- `quic_initial_4pda.to.bin` вернулся в `strategies/general-exp`: файл есть
  в репозитории Flowseal, его просто не было в списке загрузки. Стратегия
  восстановлена байт в байт.
- Список загружаемых .bin больше не задаётся вручную. `tools/update-lock.sh`
  перечисляет каталог `bin/` через GitHub API, а `zapret-setup` берёт имена
  из записей `bin_sha256` в `zapret.lock`. Захардкоженный массив остался
  только запасным вариантом.
- В список добавлены файлы, которых там не было:
  `quic_initial_4pda.to.bin`, `quic_initial_5ka_ru.bin`,
  `quic_initial_rutube_ru.bin`, `tls_clienthello_5ka_ru.bin`.

### Исправлено (сплошной обзор репозитория)
- **Тестер стратегий разрушал установку.** `utils/test-zapret.lua` копировал
  файл конфигурации поверх `/opt/zapret/config`. После перехода на загрузчик
  это означало заменить его фрагментом на десяток строк: служба переставала
  работать, а при прерывании теста система оставалась в таком виде. Теперь
  тестер пишет имя стратегии в `zapret.strategy` и возвращает исходную
  после прогона.
- Тестер по умолчанию искал каталог `configs/`, которого больше нет.
  `zapret-manager` передаёт ему каталог стратегий, файл целей и путь
  к состоянию явно.
- Тест на нестандартные символы вызывал `python3`, которого нет в контейнере
  Alpine, и в CI молча ничего не проверял. Переписан на побайтовую проверку
  через `tr`.
- Job «тесты (Alpine / busybox)» ставила `coreutils`, `findutils` и `grep`,
  то есть проверяла GNU-утилиты вместо busybox - ровно то, ради чего
  заводилась. Теперь ставится только `bash`.
- Сбор conntrack потерялся при консолидации диагностики и вернулся в снимок
  инцидента, где ему и место.
- Убраны дубли `diag_conntrack_discord` и `diag_process_uptime`.
- `.gitignore` ссылался на пути, которых больше нет
  (`hostlists/.game_filter.enabled`, `utils/log`).

### Исправлено (второй проход по репозиторию)
- **Плановый перезапуск не снимал слепок.** Договаривались, что таймер
  сохраняет состояние перед перезапуском - иначе обходная мера уничтожает
  ровно те данные, ради которых заводилась. Helper писал только строку
  в лог. Теперь он сохраняет процессы, счётчики nfqueue и conntrack в
  `/var/log/zapret-autorestart.d/` (права 700, файлы 600, хранятся
  последние 30). Пользовательский `~/.local/state` для этого не годится:
  helper работает от root, где `HOME=/root`.
- **Переустановка стирала config и выбранную стратегию.** `install_zapret`
  сносит `/opt/zapret` целиком, поэтому обещание «ручные правки config
  уважаются» не выполнялось при повторном запуске `setup.sh`. Теперь
  `config`, `zapret.strategy` и `zapret.fixes` переносятся через
  переустановку.
- Если контрольной суммы `config` нет (установка старше механизма или
  состояние удалили), обновление больше не пропускается молча: задаётся
  вопрос, а прежний файл сохраняется как `config.bak`.
- `zapret-setup --uninstall` не убирал helper планового перезапуска, лог
  и слепки.
- Отчёт для issue подхватывает последний слепок планового перезапуска.

### Добавлено (второй проход)
- Интеграционные тесты самого загрузчика: сборка `NFQWS_OPT` из стратегии
  и фиксов, слияние портов game filter, порядок правил (фиксы раньше
  стратегии), откат на `general` при неизвестном имени, пути с `../`
  и синтаксической ошибке во фрагменте.
- Тест генерируемого helper'а планового перезапуска.

### Исправлено (по второму прогону CI на Alpine)
- Счётчик перезапусков за 7 дней использовал `date -d "-N days"` -
  расширение GNU. В busybox граница получалась пустой, срабатывал запасной
  путь, и считались все записи лога независимо от давности. Арифметика дат
  переписана на целочисленный номер дня (JDN), без внешних расширений.
- `date -r <файл>` в BSD-userland означает не файл, а число секунд. Время
  изменения файла теперь берётся через `stat` в двух синтаксисах,
  с `date -r` как последним запасным вариантом.
- В линтер переносимости добавлено правило на `date -d`.

### Добавлено (поддерживаемость)
- `docs/architecture.md` - как устроен проект: три уровня, загрузчик
  стратегий и его неочевидные следствия, назначение модулей `lib/`,
  объяснение решений, которые иначе выглядят странно (права по факту
  писабельности, слой совместимости, разрешение симлинков, `exec` после
  обновления), и раздел «чего в проекте намеренно нет».
- `DEPRECATIONS.md` - реестр кода, который должен быть удалён: что, где,
  после скольких релизов и почему нельзя удалить прямо сейчас. Тест сверяет
  реестр с реальностью, чтобы он не превратился в ещё один устаревший файл.

### Изменено
- В NixOS таблица старых имён называлась `legacyConfigNames`, хотя речь
  давно про стратегии. Переименована в `legacyStrategyNames` в обоих файлах.
