# 🏗️ Как устроен проект

Документ для тех, кто собирается что-то менять в коде. Пользовательская
документация — в [README](../README.md).

## Что вообще происходит

Проект не обходит блокировки сам. Обходом занимается
[zapret](https://github.com/bol-van/zapret) от bol-van, который ставится в
`/opt/zapret` и запускается системной службой. Наша задача — три вещи:

1. поставить zapret и настроить службу на полутора десятках дистрибутивов
   и семи системах инициализации;
2. дать выбирать стратегию обхода и менять её в одно действие;
3. дать возможность понять, что сломалось, когда обход перестал работать.

## Три уровня

```
  пользователь
      |
      v
  bin/*            команды: setup, config, manager, selinux
      |
      v
  lib/*.sh         модули: пути, права, службы, списки, диагностика
      |
      v
  /opt/zapret      сам zapret + наш config-загрузчик + фрагменты
```

Правило: `bin/` содержит сценарии и диалог с пользователем, `lib/` — логику
без вывода меню. Модули из `lib/` не подключают друг друга: их подключает
скрипт из `bin/` в нужном порядке. Поэтому в шапке каждого модуля стоят
директивы `# shellcheck source=` — иначе статический анализатор не знает,
откуда берутся общие функции.

## Загрузчик стратегий — сердце проекта

Раньше каждая стратегия была самостоятельным конфигом на 168 строк, из
которых ~160 совпадали. Двадцать одна штука, изменение общего параметра —
двадцать одна правка.

Сейчас так:

```
/opt/zapret/config            общий загрузчик (форк config от bol-van)
/opt/zapret/strategies/*      фрагменты по ~11 строк: только NFQWS_STRATEGY_OPT
/opt/zapret/fixes/*           дополнения поверх любой стратегии
/opt/zapret/zapret.strategy   имя выбранной стратегии, одна строка
/opt/zapret/zapret.fixes      список включённых фиксов
```

`config` сорсится init-скриптами zapret при каждом старте службы. Он читает
состояние, подключает выбранный фрагмент и включённые фиксы, сливает списки
портов и собирает `NFQWS_OPT`.

Отсюда следуют вещи, которые неочевидны, пока не наступишь:

- **Смена стратегии — это запись одной строки**, а не подмена файла
  конфигурации. Всё, что копирует что-либо поверх `/opt/zapret/config`,
  ломает установку.
- **Правила фиксов идут перед правилами стратегии.** В nfqws выигрывает
  первый подошедший профиль, то есть фикс может перекрыть стратегию. Это
  проверяется тестом.
- **Загрузчик выполняется от root при каждом старте службы.** Поэтому
  `/opt/zapret` обязан принадлежать root: иначе любой процесс от имени
  пользователя получает выполнение своего кода от root.
- **Битый фрагмент не убивает службу.** Загрузчик проверяет имя, `sh -n`
  и непустой результат, при неудаче откатывается на `general`.
- `config` — это форк шаблона от bol-van. Когда апстрим добавит новую
  переменную, наш форк её не задаст. Пока это ловится только глазами.

## Модули lib/

| Модуль | За что отвечает |
|---|---|
| `paths.sh` | все пути в одном месте: XDG, `/opt/zapret`, состояния |
| `common.sh` | вывод, вопросы, повышение прав, запись в защищённые пути |
| `compat.sh` | обёртки над тем, чего нет в busybox и BSD-userland |
| `service.sh` | службы поверх семи систем инициализации |
| `strategy.sh` | выбор стратегии, включение фиксов, валидация фрагментов |
| `lists.sh` | ipset, game filter, домены, блок в `/etc/hosts` |
| `nfqws.sh` | разбор фрагментов, проверка ссылок на файлы |
| `update.sh` | обновление проекта, резервные копии, откат, состояние |
| `lock.sh` | чтение `zapret.lock`, проверка контрольных сумм |
| `distro.sh` | определение дистрибутива и пакетного менеджера |
| `incident.sh` | слепки состояния перед перезапуском |
| `diag.sh` | `doctor` и отчёт для issue |
| `autorestart.sh` | плановый перезапуск (обходная мера, см. ниже) |
| `uninstall.sh` | удаление всего установленного |

## Решения, которые выглядят странно, пока не знаешь причину

**Права запрашиваются по факту, а не по предположению.** `write_out` и
соседние функции сначала проверяют, писабелен ли путь, и зовут `sudo`
только если нет. Причина: на машинах со старой установки `/opt/zapret`
принадлежит пользователю, и код должен работать в обоих случаях. Побочный
эффект — откат проекта на старую версию ничего не ломает.

**Есть слой `compat.sh` и линтер `tools/lint-portability.sh`.** shellcheck
такое не ловит: синтаксис верный, а нужного флага у утилиты в конкретном
дистрибутиве нет. Каждое правило линтера появилось после реальной находки:
`ps -p` не работает в busybox, `date -d "-7 days"` тоже, `date -r файл`
в BSD означает другое, `sed -i` требует суффикс. Если добавляете вызов
внешней утилиты — проверьте, что она ведёт себя одинаково в GNU, busybox
и BSD, иначе заверните её в `compat.sh`.

**`bin/*` разрешают симлинки на себя.** Команды в `~/.local/bin` — симлинки,
а `pwd -P` раскрывает каталог, но не сам файл. Без цикла с `readlink`
скрипт ищет `lib/` рядом с симлинком и падает.

**Обновление проекта заканчивается `exec`.** Bash дочитывает скрипт с диска
по ходу выполнения: продолжать работу после того, как файл заменили,
нельзя — выполнится середина уже другого файла.

**Состояние живёт вне каталога проекта.** `~/.local/state/...` — снимки,
резервные копии, логи. Поэтому обновление может очищать каталог проекта
целиком, не разбирая исключений.

## Тесты

```bash
bash tests/run.sh               # ~180 проверок, без внешних зависимостей
bash tools/lint-portability.sh  # непереносимые конструкции
shellcheck bin/zapret-* lib/*.sh
```

Тесты намеренно написаны на чистом bash, без bats: лишняя зависимость ради
полутора сотен проверок не окупается, а так они запускаются везде, где есть
bash. Реальная система не трогается — `sudo`, `systemctl`, `/proc`,
`/etc/hosts` и `/opt/zapret` подменяются песочницей.

Отдельно стоит знать про два вида тестов:

- **интеграционные для загрузчика** — `config` сорсится в отдельной оболочке
  с подставным `ZAPRET_BASE`, и проверяется собранный `NFQWS_OPT`. Это
  единственное место, где проверяется поведение, которое реально увидит
  служба;
- **сверка списков** — что `zapret.lock`, `tests/fake-binaries.txt`, ссылки
  во фрагментах и списки имён в `nixos/` не разъехались между собой.

В CI пять job. Самая важная и самая обманчивая — прогон тестов на
`alpine:latest`: туда намеренно не ставится ничего, кроме `bash`, чтобы
остальные утилиты были штатным busybox. Один раз она уже стояла с
установленными `coreutils` и проверяла совсем не то, ради чего заведена.

## Чего в проекте намеренно нет

**bats, make, конфигурационные форматы.** Всё, что можно сделать на bash
и текстовом файле, сделано так: аудитория проекта — люди, которые правят
скрипты, а не собирают их.

**Автоматической смены стратегии.** Стратегии со временем перестают
работать, но выбирать замену должен человек: критерий «работает» тут не
формализуется.

**Периодического перезапуска по умолчанию.** `autorestart.sh` существует
как обходная мера для случая, когда через несколько часов часть трафика
перестаёт обходиться. Он выключен по умолчанию, снимает слепок состояния
перед каждым перезапуском и должен быть удалён целиком, когда причина
найдётся. Если вы читаете это и причина уже известна — удалите модуль,
а не оставляйте «на всякий случай».
